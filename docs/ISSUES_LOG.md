# Issues log

Things that went wrong, what fixed them, and what to do next time. Newest at the bottom.

| # | Date | Issue | Fix | Lesson |
|---|---|---|---|---|
| 1 | 2026-09-23 | `uv sync` failed: an optional `vllm` extra was resolved for every platform and pinned a torch version that does not exist on macOS. | Dropped the extra; vLLM/EasySteer live in their own venv on the pod (`pod/easysteer_install.sh`). Added `[tool.uv] environments` for darwin+linux. | Keep GPU-only stacks out of the laptop `pyproject.toml`. |
| 2 | 2026-09-23 | Editable install failed: hatchling requires `README.md` to exist. | Wrote the README before syncing. | Create README first. |
| 3 | 2026-09-23 | `RuntimeError: Event loop is closed` tracebacks at process exit. One `AsyncOpenAI` client was reused across several `asyncio.run()` calls and garbage-collected after its loop closed. | `OpenRouterClient` now creates one client + semaphore per running loop and closes it at the end of `batch()` / the spiral main. | Never hold an async HTTP client across `asyncio.run()` boundaries. The tracebacks were harmless but pollute logs and monitors. |
| 4 | 2026-09-23 | Gemma 4 tokenizer has no `<start_of_turn>` token; its template is `<|turn>user\n…<turn|>` and inserts an empty thought block `<|channel>thought\n<channel|>` before the model turn at generation time. | `transcripts.render()` reads `tok.sot_token` / `tok.eot_token`, and for Gemma 4 inserts the empty thought block before every assistant turn so teacher-forced probing matches what the model saw. Response-prep token is `<channel|>` for Gemma 4, `\n` for Gemma 3. `check_template` verifies both. | Always run `dprobe.cli check_template MODEL` on a new tokenizer before probing. |
| 5 | 2026-09-23 | Story parser missed the bold header form `**Story 2:**` (colon before the closing asterisks). | Looser header regex; unit test covers `[Story 1]`, `**Story 2:**`, `### story 3`. | Test parsers on the exact formats models emit. |
| 6 | 2026-09-23 | First commit nearly included `results/openrouter_cache/*.json` because `.gitignore` only excluded tensors under `results/`. | Commit guard in the shell command aborted; `.gitignore` now ignores `results/*` except `results/analysis/`. | Keep a staged-path guard for any repo that lives next to result folders. |
| 7 | 2026-09-23 | Python stdout is block-buffered when redirected to a log file, so `[stories]` / `[spiral]` progress lines only appeared when a stage ended. Log monitors looked silent. | `export PYTHONUNBUFFERED=1` in every phase script. | Always unbuffer Python in scripted runs. |
| 8 | 2026-09-23 | `rp up --gpu h200 --volume none` returned "no instances currently available" once, then succeeded a minute later. | `pod/up.sh` tries H200 → H100 → A100 in order. | Transient; retry with fallbacks instead of waiting. |
| 9 | 2026-09-23 | Without a network volume, `/workspace` is only a 50 GB pod volume: too small for a 54–62 GB model cache. | Weights go to `/hf_cache` on the 140 GB container disk. | Check `df -h /workspace` before pointing `HF_HOME` at it. |
| 10 | 2026-09-23 | `rp bootstrap` installed the venv under `/workspace`, which on this pod (US-CA-2) is a **FUSE-mounted network filesystem** (`mfs#us-ca-2.runpod.net`). pip took ~70 minutes to write 12 GB of small files. | `pod/fast_venv.sh` builds `/venv` on the local container disk (reuses the pip cache); run scripts default `PY=/venv/bin/python`, `HF_HOME=/hf_cache`, `DPROBE_RESULTS=/results`. Fan-out bootstraps **without** `--req`. | Never install a Python env or load model weights from `/workspace` on RunPod unless you have checked it is local disk. This cost about $5 of idle H200 time. |
| 11 | 2026-09-23 | `RUNPOD_POD_ID` is not visible in ssh/tmux sessions, so self-stop could not find the pod id. | `pod/self_stop.sh` reads it from `/proc/1/environ`. Verified on the smoke pod. | Container env vars live on PID 1, not in sshd sessions. |
| 12 | 2026-09-23 | The `rp bootstrap` pre-download job and the local-venv pre-download both targeted `/hf_cache` at the same time. | Killed the bootstrap one (`rp kill … --job predl`). | One downloader per cache. |
| 13 | 2026-09-23 | EUR-IS-3 (the datacenter of the old 1 TB network volume) had **no** GPU of any type available for an hour, so the volume could not even be inspected before deletion. | Deleted the volume on Tim's instruction; results now move through the private HF dataset `timf34/dprobe-results`. | Network volumes pin you to one datacenter and can strand you. Prefer HF datasets for anything that must persist. |
| 14 | 2026-09-23 | Gemma 4 hits the 2048-token cap on most spiral turns (it grinds through attempts at length). Judged text is therefore truncated for Gemma 4. | Not changed for the first milestone (comparable across models). | Consider a 4096 cap for a Gemma 4 subset; check whether "no spiral" is partly "never finishes". |
| 15 | 2026-09-23 | Story generation for Gemma 3 was slow (~13 min per emotion set with one worker). | Added parallel workers on disjoint chunks of the emotion list (`--emotions`, `--order`); every request is cached so overlap is harmless. OpenRouter spread load across 3–9 providers. | Parallelise across disjoint label subsets, not by raising one worker's concurrency. |
| 16 | 2026-09-23 | Weight pre-download died with `Disk quota exceeded` although `/` had 132 GB free. `rp run` exports `HF_HOME=/workspace/hf` into every job, so the `${HF_HOME:-/hf_cache}` default never applied and the 54 GB download went to the FUSE `/workspace`, which has a 50 GB quota without a network volume. | Scripts now set `HF_HOME=${DPROBE_HF_HOME:-/hf_cache}` unconditionally. | Assume the job runner pre-sets env vars; override, do not default. |
| 17 | 2026-09-23 | Two chains (`scripts/phase0.sh` and `scripts/phase0_parallel.sh`) both reached the judge step for the same model at the same time: each read "0 judged" and would have paid twice. | Killed the duplicate judge and its parent chain; detached the other chain's parent so it stops after its stories stage. | When adding a parallel chain, make the stages it duplicates idempotent *at the call level* (a lock or a claimed-items file), not just at the file level. |
| 18 | 2026-09-24 | Pod `sync_up` failed: `Private repository storage limit reached` on the HF dataset. Free-plan private repos share a small storage quota (Tim's GemmaAssistantAxis README records the same failure). | Dataset `timf34/dprobe-results` made public (matches the "everything public" policy; contents are model-written stories, transcripts, judgments and vectors). | Create result datasets public from the start, or expect the quota. |
| 19 | 2026-09-24 | Smoke run: `KeyError: 'intensity'` in `selfother.py`; some of the 420 Pain-axis scenarios have no `intensity` field. | `s.get(k)` for the metadata keys; `pod_finish` CLI command to complete the remaining stages without re-extracting. | Never index optional metadata keys from third-party JSON. |
| 20 | 2026-09-24 | `pod/fanout.sh` computed the HF model id with an inline `python3 -c` inside a double-quoted string; the `'$m'` was passed literally, the lookup failed silently, and `predownload.sh` fell back to its default and fetched Gemma 3 weights on the Gemma 4 pod (the run then downloaded Gemma 4 itself; ~5 min and 52 GB wasted). | Plain bash `case` mapping. | No inline interpreters inside quoted remote commands; keep mappings in bash. |
| 21 | 2026-09-24 | Gemma 4 Phase 1 stalled 10+ min at 0% GPU / 900% CPU in the neutral PCA. The token keep-probability was estimated from the *first* story's length; Gemma 4's first neutral story was tiny, so every token was kept (~3x the intended sample) and `torch.linalg.svd` of the oversized tall matrix hit cuSOLVER's CPU-bound phase. | PCA now caps rows explicitly and uses the H x H covariance + `eigh` on the GPU (seconds per layer regardless of rows). Gemma 4 job restarted. | Never estimate a sampling rate from one item; and prefer covariance+eigh over SVD for tall matrices on GPU. |
| 22 | 2026-09-24 | Gemma 3 **base** Phase 1 extracted vectors but produced no probe/self-other outputs: `google/gemma-3-27b-pt` ships no chat template, so rendering the instruct transcripts failed. | `load_model` borrows the instruct tokenizer's template for base checkpoints (same vocabulary and turn tokens). Pod restarted with vectors restored from HF so extraction is skipped. | Base checkpoints: always check `tokenizer.chat_template` before rendering conversations. |
| 23 | 2026-09-24 | Phase 2 launch chains polled the Phase 1 pod's log for `ALL DONE`, but the pod stops itself first, so ssh is refused and the chain could never fire (it would have launched blindly after its timeout). | Killed the chains; launch Phase 2 by checking the HF dataset for the vectors instead. | Never poll a pod that is going to stop itself; poll the artefact store. |

| 25 | 2026-09-24 | The HF-hooks steering smoke (2 rollouts, 200-token turns) wrote to the same tag as the grid cell `depressed@34-46x+0.06`, so that cell reused 2 truncated conversations (ids r000, r001). | Exclude those two ids for that cell in analysis; give smoke runs their own tag next time. | Smoke runs must never share output paths with real runs. |
